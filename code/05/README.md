# 05 - Board bring-up, self-tests

[Build log](https://hackaday.io/project/206556-a-tiny-sieve-lehmers-math-machine-in-attinys/log/250782-the-modulus-chorus-rehearses)

Thirty ATtiny412 cards in a stripboard backplane, checked before a run. The
card firmware gains a CRC-8 checked I2C protocol with a readable status, and a
hand-written interrupt handler that drives VOTE in its first instruction.

## Signals

- **REQ** — Pico output (GP17) to every card (PA6). Each rising edge makes
  every armed card drive VOTE from its ring and advance its phase by one.
- **VOTE** — one wire shared by all thirty cards (PA3) and read by the Pico
  (GP21). No pull-up resistor is fitted: the line is held high by the cards'
  internal pull-ups in parallel, about 1.2 kOhm.
- **I2C** — Pico (GP18 SDA, GP19 SCL) to every card (PA1, PA2) and to an
  SSD1306, at 100 kHz. Cards take no I2C traffic while armed, so REQ is held
  low for every transaction.
- **LED** — PA7 on each card, lit whenever that card is driving VOTE low.

Measured with all thirty cards fitted: 947 ns from a REQ rising edge to VOTE
low, and 1.684 us from the same edge to VOTE settled high.

## ATtiny412 firmware — `avr/`

`src/hal/hal_gpio.c` holds the REQ handler: six assembly instructions with four
registers reserved across the build, and the next phase's port-direction byte
precomputed, so the first instruction executed drives VOTE. `src/task/task_cmd.c`
decodes five commands, each ending in a CRC-8 PEC, and answers every one with a
response code the host reads back. `src/task/task_sieve.c` holds the ring.

Build and flash over serial UPDI, once per card with a distinct I2C address:

    cd avr/src
    make clean flash ADDR=0x10

Set `BASE` and `PORT` for your toolchain and UPDI adapter. Host tests of
`task_cmd.c` and `task_sieve.c` against vectors generated by
`avr/test/ref/model.py`, no hardware needed: `cd avr/test/host && make test`.

## Flashing a batch — `jig/`

`flash_batch.py` runs on the PC and walks a tray of cards one at a time: build
both images, flash the log 4 diagnostic image, run its electrical checks, flash
the log 5 image for the next free address, then check over I2C that the card
answers there and steps its ring. A card that fails any step does not consume
an address.

    python3 jig/flash_batch.py                # batch loop over 30 addresses
    python3 jig/flash_batch.py --verify 0x17  # functional check only

## Pico host — `rpi/` (MicroPython)

`card.py` is one card, `bank.py` all thirty plus the shared REQ and VOTE lines.
`selftest.py` runs the five pre-run checks — roll call, REQ bridge, idle VOTE,
LED walk, and one card at a time against its own ring. `timing.py` loads one
common ring and drives REQ from a hardware PWM, so the scope sees a steady
pattern. `panel.py` drives the OLED, and does nothing if none is fitted.

    cd rpi
    mpremote mount . exec "import selftest; selftest.main(30)"
